# 智筛招聘一期功能规格

## 1. 文档信息

- 功能编号：001
- 状态：需求已澄清，可进入技术规划
- 创建日期：2026-08-08
- 最近更新：2026-08-08
- 决策依据：`docs/项目设定记录.md`
- 接口依据：`docs/italent-resume-sync.md`
- 适用范围：单一北森租户的智筛招聘一期

## 2. 目标

构建一个面向 HR 和招聘管理员的内部系统，通过北森 API 同步候选人、岗位投递、岗位信息和简历文件；按岗位展示投递记录；使用管理员确认的岗位评估规则批量生成可追溯的 AI 分析报告；由 HR 完成人工筛选、负责人送审、人才库管理和软删除恢复。

系统必须提高简历初筛和负责人审核效率，但不得代替人工做出招聘决定。

## 3. 角色

### 3.1 HR

- 查看全部岗位、候选人、简历和 AI 报告。
- 发起或重新执行 AI 分析。
- 添加自己的备注，使用团队标签。
- 发起负责人审核。
- 导入或移出人才库。
- 将人才库候选人推荐到岗位。
- 软删除投递记录。
- 导出单份报告和脱敏汇总表。

### 3.2 管理员

- 拥有全部 HR 权限。
- 创建、停用、解锁和重置用户账号。
- 创建、修改和发布岗位评估规则。
- 管理北森同步配置和手动同步。
- 查看模型调用统计、Token 和预估费用。
- 恢复 3 天回收站内的投递和人才库记录。
- 管理系统设置。

### 3.3 审核负责人

- 无系统账号。
- 通过邮件中的直接链接查看本次送审的候选人姓名、岗位和简历。
- 对每份简历提交“通过”“不通过”或“待讨论”及对应备注。
- 不得查看 AI 报告、HR 备注、人才库信息、其他岗位投递或模型过程。
- 不得下载简历。

### 3.4 运维人员

- 维护部署环境、密钥、模型配置、邮件配置和加密备份。
- 在系统整体故障时执行灾难恢复。
- 不通过灾备执行普通候选人恢复。

## 4. 优先用户场景

### US-01 北森同步与岗位浏览（P1）

作为 HR，我希望系统自动从北森同步候选人、实际投递岗位和简历，使我可以按岗位查看最新投递记录，而无需人工导出上传。

**验收条件**

1. 首次同步可遍历全部批次，并保存候选人和投递关系。
2. 后续增量同步不会重复创建相同 `applicantId` 或 `applicationId`。
3. 同一候选人的多个岗位投递分别显示。
4. 有效岗位与历史岗位分开展示。
5. 同步失败显示接口、批次和可理解的失败原因。

### US-02 岗位规则准备与发布（P1）

作为管理员，我希望基于北森 JD 生成岗位评估规则草稿，修改并发布后供 AI 分析使用。

**验收条件**

1. 系统分别显示北森原始 JD 和系统评估 JD。
2. AI 可从 JD 生成硬性要求、维度、权重、加分项和等级区间草稿。
3. 未发布规则的岗位不能发起简历分析。
4. 北森 JD 变化时不覆盖当前规则，只提示差异。
5. 发布新版本不改变历史报告。

### US-03 批量 AI 简历分析（P1）

作为 HR，我希望从岗位列表选择多份简历异步分析，以便快速获得统一、可解释的岗位匹配报告。

**验收条件**

1. 默认单批最多选择 20 份，管理员可在 1–50 范围内调整。
2. HR 离开页面后任务继续执行。
3. 每份简历显示等待、分析中、成功或失败状态。
4. 单项失败不影响同批其他项目，并可单独重试。
5. 相同简历版本和规则版本默认复用已有报告。
6. 重新分析生成新版本，不覆盖历史报告。

### US-04 人工筛选与负责人审核（P1）

作为 HR，我希望对完成分析的投递记录执行送审、入库或删除，并跟踪负责人审核结果。

**验收条件**

1. 未完成 AI 分析的投递记录不能执行后续筛选操作。
2. 负责人审核、导入人才库和删除不是互斥状态。
3. 多份简历发送给同一负责人时只生成一封邮件和一个批量审核链接。
4. 不同负责人自动拆分邮件和审核任务。
5. 负责人提交的每份结果独立回写。
6. HR 可以按审核状态筛选。
7. 审核通过后只由 HR 线下或在现有招聘系统推进面试。

### US-05 人才库管理与复用（P2）

作为 HR，我希望将筛选出的候选人加入人才库、检索并推荐到新岗位，以便复用已有候选人资源。

**验收条件**

1. 人才库以 `applicantId` 去重。
2. 只有 HR 主动操作才能入库或恢复，系统不得自动入库。
3. 支持结构化搜索、模糊搜索和组合筛选。
4. 支持团队标签和带作者的内部备注。
5. 可将人才库候选人推荐到有效岗位并重新分析。
6. 后续北森正式投递可与人才库推荐记录关联。

### US-06 删除、恢复与同步排除（P1）

作为 HR，我希望删除不再展示的投递；作为管理员，我希望在 3 天内恢复误删记录。

**验收条件**

1. 软删除后记录立即从业务列表隐藏。
2. 管理员可在 3 天内恢复。
3. 3 天后业务数据被清理。
4. 最小排除标识继续阻止北森重新导入同一 `applicationId`。
5. 新的 `applicationId` 正常同步。
6. 删除正在送审的记录会撤回对应审核项。

### US-07 账号与系统管理（P1）

作为管理员，我希望管理独立账号、岗位规则、同步和系统配置，确保只有授权人员使用系统。

**验收条件**

1. 系统不开放注册。
2. 首个管理员通过部署配置初始化，密码不在代码中。
3. 管理员可一键重置用户密码并仅查看一次临时密码。
4. 连续失败登录触发锁定。
5. 会话按无操作时间和最长时长过期。
6. 管理员与 HR 权限符合本规格。

### US-08 可见的运行状态和通知（P2）

作为 HR 或管理员，我希望看到同步、分析、审核和外部服务状态，以便识别失败并采取行动。

**验收条件**

1. 首页显示新增简历、分析完成或失败、负责人审核结果。
2. 负责人送审以外的业务事件不发送邮件。
3. 邮件和模型失败显示原因并支持重试。
4. 管理员可查看模型连接状态、调用量和预估费用。

## 5. 功能需求

### 5.1 北森认证与同步

- **FR-001** 系统必须通过一个固定北森连接器账号获取访问令牌并缓存使用。
- **FR-002** 系统必须支持首次全量同步候选人 ID。
- **FR-003** 系统必须按 `nextBatchId` 继续请求，直到 `isLastBatch=true`。
- **FR-004** 系统必须支持按时间窗口拆分全量同步并对 ID 去重。
- **FR-005** 系统必须按接口限制批量获取候选人个人资料和简历模块。
- **FR-006** 系统必须获取候选人的实际投递记录，并保存 `applicationId`、`applicantId`、岗位标识、岗位名称、岗位类型、状态、投递时间和来源。
- **FR-007** 系统必须使用 `applicantId` 作为候选人唯一标识，使用 `applicationId` 作为北森投递唯一标识。
- **FR-008** 接口缺失 `applicantId` 或 `applicationId` 时，系统必须将该记录标记为同步失败，不得猜测。
- **FR-009** 系统必须默认每 10 分钟同步候选人、投递和简历更新。
- **FR-010** 系统必须默认每 1 小时同步岗位、JD 和岗位状态。
- **FR-011** 系统必须每天执行一次带重叠时间窗口的校准同步。
- **FR-012** 管理员必须可以手动触发全局或指定范围同步。
- **FR-013** 同步必须统一限流并对可重试错误执行重试。
- **FR-014** 同步任务必须记录开始时间、结束时间、范围、批次、成功数、失败数和失败原因。
- **FR-015** 系统必须显示岗位状态来源和最后同步时间。
- **FR-016** 北森无法提供岗位状态时，HR 必须可以手动设置岗位为有效或历史。
- **FR-017** 手动岗位状态在取消手动控制前不得被北森同步覆盖。
- **FR-018** 北森岗位重新开放后，在无手动覆盖时必须恢复为有效岗位。
- **FR-019** 系统必须只同步已批准的数据模块，额外模块只能由管理员启用。

### 5.2 候选人、投递和岗位

- **FR-020** 同一候选人的多个岗位投递必须独立存在。
- **FR-021** 候选人基础资料和简历文件可以在多个投递之间共享。
- **FR-022** 系统不得根据姓名、电话或邮箱自动合并不同 `applicantId`。
- **FR-023** 北森同步的候选人字段必须只读。
- **FR-024** 岗位关闭后必须进入历史岗位列表并保留既有业务数据。
- **FR-025** 历史岗位默认不得发起新分析或送审。
- **FR-026** HR 必须可以临时启用历史岗位继续处理。
- **FR-027** 岗位列表必须默认展示有效岗位，并允许切换历史岗位。

### 5.3 简历列表、详情和文件

- **FR-028** 岗位投递列表必须展示姓名、投递时间、来源、简历更新时间、AI 状态、分数、等级、审核状态和人才库状态。
- **FR-029** 岗位投递列表必须默认按投递时间倒序。
- **FR-030** 列表必须支持按时间、AI 状态、推荐等级、审核状态和人才库状态筛选。
- **FR-031** 列表必须支持姓名模糊搜索、手机号和邮箱精确搜索，以及公司、学校和技能关键词搜索。
- **FR-032** 搜索必须支持当前岗位和全部岗位范围。
- **FR-033** 点击候选人必须进入统一候选人详情页。
- **FR-034** 候选人详情必须显示基本资料、最新简历、历史简历版本、全部岗位投递、对应报告、审核状态、标签和备注。
- **FR-035** 系统必须保留北森原始文件作为正式源文件，并优先使用标准 PDF 进行网页预览。
- **FR-036** HR 必须可以逐份下载原始简历；一期不得提供批量打包下载。
- **FR-037** 系统必须支持 PDF、DOC、DOCX 的文本提取，并对扫描 PDF 或图片执行 OCR。
- **FR-038** 文本提取质量过低时不得生成正式评分，必须显示原因并允许重试或补充文件。
- **FR-039** OCR 和解析文本只能用于分析，不得替换原始简历。
- **FR-040** 系统必须通过文件摘要识别简历变化。
- **FR-041** 已用于分析、送审或人才库的旧简历版本必须保留。
- **FR-042** 未用于任何业务流程的旧文件可以被新版本替换。

### 5.4 岗位评估规则

- **FR-043** 系统必须分别保存北森原始 JD 和系统评估 JD。
- **FR-044** 北森原始 JD 更新不得直接覆盖系统评估 JD。
- **FR-045** 系统必须向管理员显示 JD 差异。
- **FR-046** 管理员必须可以选择采用新版、保留当前版或手动合并。
- **FR-047** AI 必须能够从 JD 生成岗位规则草稿。
- **FR-048** 岗位规则必须包括硬性要求、评分维度、权重、加分项和推荐等级区间。
- **FR-049** 只有管理员可以创建、修改和发布岗位规则。
- **FR-050** 未发布岗位规则的岗位不得发起分析。
- **FR-051** 岗位规则每次发布必须生成版本并记录发布人和时间。
- **FR-052** 运行中的分析必须继续使用启动时的规则版本。

### 5.5 AI 分析

- **FR-053** 系统提示词必须由开发或运维配置，不得向管理员或 HR 开放编辑。
- **FR-054** 系统提示词必须版本化。
- **FR-055** 一期必须使用一个经过批准的模型。
- **FR-056** 模型变更必须生成新模型版本，历史报告不得自动重算。
- **FR-057** 发送给模型的候选人内容必须先移除不必要的直接身份信息。
- **FR-058** 单批默认上限必须为 20，管理员可在 1–50 范围调整。
- **FR-059** 分析必须作为后台异步任务执行。
- **FR-060** 每个分析项必须显示等待、分析中、成功或失败。
- **FR-061** 单项失败不得影响同批其他分析项。
- **FR-062** 模型异常必须自动重试 3 次。
- **FR-063** 重试失败必须保留任务并允许 HR 后续重试。
- **FR-064** 系统不得静默切换其他模型。
- **FR-065** 相同简历版本和规则版本已有成功报告时必须默认复用。
- **FR-066** HR 必须可以主动重新分析，并填写原因。
- **FR-067** 重新分析必须生成新报告版本。
- **FR-068** 报告必须记录候选人、岗位、简历版本、规则版本、提示词版本、模型版本和生成时间。
- **FR-069** 报告必须输出 0–100 匹配分和总体推荐等级。
- **FR-070** 默认等级必须为：80–100 且无明确硬性不满足为优先评估；60–79 或信息不足为建议人工复核；0–59 或明确硬性不满足为匹配度较低。
- **FR-071** 推荐等级只能用于排序和筛选，不得自动触发业务操作。
- **FR-072** 报告必须逐项展示硬性要求状态和简历证据。
- **FR-073** 报告必须展示各评分维度的分数、权重和依据。
- **FR-074** 报告必须展示优势、风险、不足、缺失信息和矛盾信息。
- **FR-075** 报告必须展示面试重点、注意事项和分类面试问题。
- **FR-076** 缺乏依据时必须明确说明，不得编造。
- **FR-077** AI 原始报告不得编辑；HR 备注和人工结论必须独立保存。
- **FR-078** HR 必须可以导出单份 PDF 报告和脱敏 Excel 汇总，系统不记录导出操作。
- **FR-079** 只有管理员可以查看模型调用量、Token 和预估费用。
- **FR-080** 管理员可以设置月度费用告警，但告警不得自动停止分析。

### 5.6 人工筛选与负责人审核

- **FR-081** 只有完成 AI 分析的投递记录才允许执行负责人审核、人才库入库或删除。
- **FR-082** 负责人审核、人才库入库和删除必须作为独立操作。
- **FR-083** 岗位负责人关系必须按用户后续提供的数据配置。
- **FR-084** 单一负责人岗位必须直接使用该负责人；多负责人岗位必须由 HR 选择一名或多名负责人。
- **FR-085** 同一负责人同一批次必须只收到一封邮件和一个批量审核链接。
- **FR-086** 选择不同负责人时必须拆分为不同审核任务和邮件。
- **FR-087** 邮件必须包含岗位、待审核数量、截止时间和审核链接，不得包含附件或 AI 报告。
- **FR-088** 审核链接不得要求登录或验证码。
- **FR-089** 审核链接必须使用不可猜测标识，并限制为指定审核任务。
- **FR-090** 链接默认有效 72 小时，可选 24 小时、72 小时或 7 天。
- **FR-091** HR 必须可以撤销未完成链接。
- **FR-092** 全部审核提交后链接必须立即失效。
- **FR-093** 修改已提交结果必须由 HR 重新开启审核并生成新链接，历史结果必须保留。
- **FR-094** 负责人只能查看候选人姓名、当前岗位和本次简历。
- **FR-095** 负责人不得下载简历或查看 AI、HR、人才库及其他岗位信息。
- **FR-096** 每份简历必须支持通过、不通过、待讨论和暂存未提交。
- **FR-097** 不通过和待讨论必须填写原因，通过的备注可选。
- **FR-098** HR 必须可以按审核状态筛选。
- **FR-099** 邮件失败必须自动重试 3 次。
- **FR-100** 重试失败必须提醒发起 HR 并允许重发。
- **FR-101** 重发必须复用仍有效链接，不得重复创建审核任务。
- **FR-102** 删除正在审核的投递必须立即撤回该审核项。
- **FR-103** 批次没有剩余审核项时链接必须失效。
- **FR-104** 恢复被删除投递后不得自动恢复旧审核流程。

### 5.7 人才库

- **FR-105** 人才库必须以 `applicantId` 作为唯一候选人主体。
- **FR-106** 只有 HR 主动操作才能导入、恢复或重新导入人才库。
- **FR-107** 候选人再次投递不得自动进入或恢复人才库。
- **FR-108** 系统可以提示候选人曾经入库。
- **FR-109** 人才库必须关联候选人的投递、岗位和简历版本。
- **FR-110** 人才库必须支持姓名、手机号、邮箱、技能、公司、学校和岗位经历搜索。
- **FR-111** 人才库必须支持标签、学历、年限、历史岗位和入库时间筛选。
- **FR-112** 一期必须使用结构化查询和关键词模糊匹配，不得依赖向量搜索。
- **FR-113** 团队标签必须对所有 HR 可见。
- **FR-114** 所有 HR 可以创建标签并为候选人添加或移除标签。
- **FR-115** 只有标签创建人和管理员可以修改或删除标签定义。
- **FR-116** 所有 HR 可以查看候选人备注。
- **FR-117** HR 只能修改或删除自己创建的备注；管理员可以删除任意备注但不得改写。
- **FR-118** 人才资料超过 24 个月未更新时必须标记可能过期，但不得自动移除。
- **FR-119** 过期资料仍可推荐到岗位，但 HR 必须确认提示。
- **FR-120** 过期资料的 AI 报告必须标记更新时间，并列为面试核实事项，不自动扣分。
- **FR-121** HR 必须可以将人才库候选人推荐到有效岗位。
- **FR-122** 人才库推荐必须创建来源为人才库推荐的本地记录，不得写回北森。
- **FR-123** 后续同岗位北森正式投递必须与本地推荐建立关联并合并展示。
- **FR-124** 正式投递带来新简历时必须提示重新分析。
- **FR-125** 移出人才库只取消人才库成员身份，不删除历史业务记录。
- **FR-126** 移出后必须隐藏 3 天供管理员恢复，随后删除人才库标签和专属备注。

### 5.8 删除、审计和数据生命周期

- **FR-127** HR 必须可以软删除岗位投递。
- **FR-128** 软删除必须立即隐藏，并在主系统保留 3 天。
- **FR-129** 只有管理员可以恢复。
- **FR-130** 删除单个投递不得影响同一候选人的其他投递。
- **FR-131** 删除投递不得自动移除人才库成员。
- **FR-132** 3 天后必须删除姓名、联系方式、简历、报告和其他业务数据。
- **FR-133** 系统必须保留该 `applicationId` 的最小排除标识，阻止同步重新展示。
- **FR-134** 新 `applicationId` 必须正常同步。
- **FR-135** 最小删除审计日志必须保留 180 天，并只包含操作人、时间、原因、恢复记录和脱敏标识。
- **FR-136** 删除审计不得包含简历正文或联系方式。

### 5.9 账号、权限和会话

- **FR-137** 系统不得开放自主注册。
- **FR-138** 管理员必须可以创建 HR 和管理员账号并设置临时密码。
- **FR-139** 首个管理员账号名可以预设，但密码必须通过部署环境初始化。
- **FR-140** 初始或重置密码首次使用后必须强制修改。
- **FR-141** 密码重置必须使全部已有会话失效。
- **FR-142** 临时密码只能向管理员展示一次。
- **FR-143** 系统必须记录密码重置操作人和时间，不得记录密码明文。
- **FR-144** 15 分钟内连续失败 5 次必须锁定账号 15 分钟。
- **FR-145** 管理员必须可以提前解锁。
- **FR-146** 系统必须记录失败时间和来源 IP。
- **FR-147** 用户 60 分钟无操作必须退出。
- **FR-148** 单次登录最长 12 小时。
- **FR-149** 系统不得提供长期保持登录。
- **FR-150** 所有 HR 可以查看全部岗位，不设置岗位级权限。
- **FR-151** 关键业务操作必须二次确认。

### 5.10 通知、部署和备份

- **FR-152** 新增简历、分析结果、分析失败和审核结果必须通过站内通知展示。
- **FR-153** 一期只有负责人送审发送业务邮件。
- **FR-154** 一期不得发送短信、企业微信或钉钉通知。
- **FR-155** 系统必须支持 Docker 方式部署到公司控制的 Linux 服务器。
- **FR-156** HR 管理界面必须限制在公司内网或 VPN。
- **FR-157** 负责人审核页面必须通过公网 HTTPS 提供，并只能访问对应任务。
- **FR-158** 服务器必须允许出站访问北森、模型和邮件服务。
- **FR-159** 数据库和文件必须每天执行加密备份。
- **FR-160** 系统必须只保留最近 7 个每日恢复点。
- **FR-161** 备份只能用于整体灾难恢复。
- **FR-162** 普通管理员不得从灾备中单独恢复候选人。

## 6. 数据实体与关系

### 6.1 Candidate

- 主标识：`applicantId`
- 包含北森只读基础资料。
- 关联多个简历版本、多个投递和一个可选的人才库成员状态。

### 6.2 Application

- 北森投递主标识：`applicationId`
- 关联一个候选人和一个岗位。
- 同一候选人可存在多个投递。
- 人才库推荐使用本地记录标识，并保留来源类型。

### 6.3 Position

- 保存北森岗位标识、名称、类型、原始 JD、状态、状态来源和最后同步时间。
- 关联多个岗位规则版本和多个投递。

### 6.4 ResumeVersion

- 关联候选人。
- 保存来源、文件摘要、原始文件、标准 PDF、解析文本、OCR 状态和质量状态。
- 被报告、审核或人才库引用后不可被覆盖。

### 6.5 PositionRuleVersion

- 保存系统评估 JD、硬性要求、评分维度、权重、加分项和推荐区间。
- 保存草稿、已发布状态、创建人、发布人和版本。

### 6.6 AnalysisReport

- 关联投递、简历版本、岗位规则版本、提示词版本和模型版本。
- 保存评分、等级、硬性要求、维度结果、证据、优势、风险、缺失信息、面试重点和问题。
- 关联独立 HR 备注和人工结论。

### 6.7 ReviewBatch 与 ReviewItem

- ReviewBatch 关联负责人、岗位、截止时间、链接状态和邮件状态。
- ReviewItem 关联一条投递及其通过、不通过、待讨论或草稿结果。

### 6.8 TalentMembership

- 关联候选人。
- 保存入库、移出、恢复、资料过期状态。
- 关联团队标签和人才库专属备注。

### 6.9 SyncJob、AnalysisJob、EmailJob

- 保存异步任务状态、重试次数、错误原因和关联对象。
- 必须支持幂等执行和单项重试。

### 6.10 ExclusionMarker 与 AuditEvent

- ExclusionMarker 保存已永久删除投递的最小 `applicationId` 排除信息。
- AuditEvent 只保存设定范围内的操作元数据。

## 7. 状态规则

### 7.1 岗位

- 有效
- 历史
- 手动有效
- 手动历史

### 7.2 AI 分析

- 未分析
- 等待
- 分析中
- 成功
- 解析失败
- 模型服务异常
- 已取消

### 7.3 负责人审核

- 未送审
- 邮件发送中
- 邮件发送失败
- 待审核
- 部分完成
- 已完成
- 已撤销
- 已过期

### 7.4 人才库

- 未入库
- 已入库
- 资料可能过期
- 已移出待恢复
- 已移出

### 7.5 投递删除

- 正常
- 软删除待恢复
- 永久清理并保留排除标识

## 8. 失败与边界行为

| 场景 | 必须行为 |
| --- | --- |
| 北森 Token 失效 | 重新获取或刷新，不得将认证失败显示为同步成功 |
| 北森批次中断 | 保存游标和范围，允许从安全位置重试 |
| 缺少 `applicantId` | 记录失败并告警，不创建猜测候选人 |
| 缺少投递接口权限 | 标记外部依赖未满足，不伪造投递数据 |
| 岗位状态不可读 | 使用人工状态降级并显示来源 |
| 临时下载 URL 过期 | 重新获取 URL，不依赖旧 URL |
| 文件损坏或加密 | 标记解析失败，保留源文件供 HR 查看 |
| OCR 质量低 | 不生成正式分数 |
| 模型超时 | 重试 3 次，失败后保留任务 |
| 单批部分失败 | 成功项保留，失败项单独重试 |
| 邮件发送失败 | 重试 3 次并通知 HR |
| 审核链接过期 | 禁止访问，HR 可生成新链接 |
| 删除正在审核的投递 | 撤回审核项；批次为空则链接失效 |
| 北森再次返回已删除投递 | 根据排除标识保持隐藏 |
| 人才库旧简历 | 提醒 HR 并在报告标记，不自动扣分 |
| 正式投递与人才推荐无法确定关联 | 由 HR 手动确认 |

## 9. 数据边界

### 9.1 默认同步

- 基本资料和联系方式
- 教育、工作、项目、实习、培训
- 技能、语言、证书、奖项
- 求职意向、实际投递、岗位
- 原始简历、标准 PDF 和必要附件

### 9.2 默认不同步

- 工资卡和银行卡
- 家庭成员和亲属申报
- 详细证件信息
- 与岗位初筛无关的自定义模块

### 9.3 模型可见范围

- 脱敏后的简历文本
- 已发布岗位规则
- 分析所需的结构化招聘字段

### 9.4 负责人可见范围

- 候选人姓名
- 当前岗位名称
- 本次送审简历在线预览

## 10. 一期范围外

- 自动联系候选人、面试邀请和面试排期
- 将人才库推荐或筛选结果写回北森
- 企业统一登录
- 企业微信、钉钉和短信通知
- 向量知识库和自然语言人才搜索
- 批量打包下载简历
- 负责人账号体系和 AI 报告访问
- AI 自动淘汰、送审、入库或删除
- 多租户和多个北森账号
- 移动端 App

## 11. 外部依赖与待提供资料

以下事项不改变产品规格，但会阻塞对应集成或生产部署：

1. 北森“应聘者投递通用信息”正式接口地址、字段和权限。
2. 正式租户是否具备职位、招聘需求、JD 和岗位状态读取权限。
3. 北森连接器 Key、Secret 和联调环境。
4. 岗位与负责人姓名、邮箱配对数据。
5. 各岗位正式 JD、硬性要求、加分项和评分权重。
6. 经公司批准的模型服务商、模型名称和 API 配置。
7. 邮件服务和发件邮箱配置。
8. Linux 服务器、内网/VPN、公网域名、HTTPS 和对象存储环境。

## 12. 开发验证成功指标

这些指标用于开发侧测试结果报告，不代表用户已完成业务验收。

- **SC-001** 全量同步在所有批次完成后产生明确完成状态，并且不存在重复 `applicantId` 或 `applicationId`。
- **SC-002** 增量同步重复执行同一时间窗口时不会创建重复记录。
- **SC-003** 抽样数据可从候选人追溯到投递、岗位、简历版本和来源。
- **SC-004** 单批 20 份简历中的每一项最终都有成功或明确失败状态，不存在静默丢失。
- **SC-005** 成功报告包含本规格定义的全部固定章节和版本信息。
- **SC-006** 相同输入默认复用报告，主动重新分析生成新版本。
- **SC-007** 负责人只能访问当前审核任务中的允许内容。
- **SC-008** 审核链接按 24 小时、72 小时或 7 天配置过期，撤销和完成后立即失效。
- **SC-009** 删除投递后业务列表和后续北森同步均不再显示同一 `applicationId`。
- **SC-010** 管理员可以在 3 天窗口内恢复，超过窗口后普通界面不可恢复。
- **SC-011** HR 与管理员权限测试符合角色定义。
- **SC-012** 登录锁定、会话超时和密码重置会话失效按设定执行。
- **SC-013** 最近 7 个每日备份恢复点可被运维识别，开发报告注明是否实际执行恢复演练。
- **SC-014** 所有未接入的正式外部能力必须在测试报告中标记为未验证。

## 13. 测试与验收职责

1. 开发侧执行自动化测试、集成测试和当前环境允许的开发验证。
2. 开发侧报告实际执行命令、通过项、失败项、未验证项和已知问题。
3. 开发侧不得将未执行的测试描述为成功。
4. 最终业务验收由用户执行并决定是否通过。
